### Transmettre l'IP du client vias X-Forwarded-IP
- Local Traffic -> Profiles -> Services -> HTTP
- Creer ou modifier le profile HTTP, qui doit être associé au VS
- Cocher **Insert X-Forwarded-IP**

Possible de le faire avec un **iRule**
Tester 
~~~
curl https://exemple.com -kI --header "X-Forwarded-For: 10.200.3.4"
~~~

Dans les logs httpd, vous verrez l'IP client

#### Avec iRule
- Local Traffic -> Virtual Server -> Resources -> iRules


### Codes HTTP
- **400** : peut se produire quand il n'y pas un profile https(server) associé au VS

### Enter the tmsh command-line interface
```sh
tmsh
```

### Create a server pool with "round-robin" load balancing
```sh
create ltm pool my_pool members add { 192.168.1.10:80 192.168.1.11:80 192.168.1.12:80 } load-balancing-mode round-robin
```

### Create an HTTP health monitor to check server availability
1. "interval" defines the time between checks, "timeout" sets the limit before marking a server as unavailable
2. "send" contains the HTTP request to send to test server responses

```sh
create ltm monitor http my_http_monitor interval 10 timeout 31 send "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n"
```

### Attach the HTTP health monitor to the pool so the LTM can check server availability
```sh
modify ltm pool my_pool monitor my_http_monitor
```

### Create a Virtual Server with a virtual IP (VIP) and associate it with the server pool

a. "destination" defines the IP address and port that internal clients will connect to

b. "ip-protocol" specifies the protocol, here TCP

```sh
create ltm virtual my_virtual_server destination 192.168.1.100:80 ip-protocol tcp pool my_pool
```

### Save the configuration to ensure that settings are applied permanently

```sh
save /sys config
```
